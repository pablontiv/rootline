# Changelog

All notable changes to this project will be documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Releases are automated via CI from conventional commits.

## [Unreleased]

### Changed

- **BREAKING**: Rootline no longer installs or supports the former OpenCode-specific `~/.config/opencode/skills/rootline` destination. OpenCode and Pi consume the shared `~/.agents/skills/rootline` symlink; Claude consumes `~/.claude/skills/rootline`. Agents upgrading an older environment must inspect and preserve the former destination themselves, retire it deliberately, run `rootline skill install` from the primary Rootline checkout, apply the emitted `plan_digest` with `--approve`, and verify with `rootline skill status`. Rootline does not discover or mutate obsolete runtime paths.
- `schema apply` now rejects invalid prospective `.stem` hierarchies before publishing actions or writing files, while preserving version-1 `stem_health[]` diagnostics and atomic per-file `.stem` replacement for accepted writes.
- `schema apply` now converges proposal and analyze writes on a bound physical target: internal aliases are supported, escaping aliases are rejected, malformed external governing ancestors surface as structured relative `yaml-valid` diagnostics in `stem_health[]`, and schema proposal targets must use the literal basename `.stem` so case-insensitive basename aliases are rejected before resolution.
- `schema apply` post-validation now shares `validate --all` document, governed-link, extraction/frontmatter, and directory-structure checks. Its summary preserves document-only counts while making directory-only failures non-green; operational scan/resolution failures remain apply errors, without rollback or changes to version-1 output and exit semantics. Closes #284.
- Hosted CI pins golangci-lint v2.14.0 so linting remains compatible with the Go 1.27 export-data format selected by the stable toolchain.
- Local Dagu scripts now normalize `umask 022` at their shared boundary, so forge pushes and nested Git hooks use the same file-mode policy as direct gate phases even when started under `umask 077`.
- Local Dagu forge actions now allow a bounded 180-second hosted-workflow registration window before watching checks, avoiding false failures during delayed GitHub Actions registration while retaining fail-fast watching, successful final rows, and exact-SHA evidence; permanent absence fails with a distinct registration timeout.
- Link resolution now proves physical containment before enumerating each directory, preventing escaped `..` targets and out-of-root symlinks from exposing filenames through fuzzy suggestions while preserving suggestions inside the governance root.

Stable releases also require the new Linux/macOS/Windows atomic-write and repair-rollback durability matrix, which requires exactly 14 matching tests before execution. Closes #321.

### Changed

- **BREAKING**: `validate` emits one envelope shape for every invocation — `rootline/validate-batch` **version 2** — including single-file runs, which previously emitted a bare `rootline/validate` object. Read a single verdict as `.results[0]`; `--field valid` becomes `--field "results[].valid"`. See the upgrade table in `docs/validate.md`.
- **BREAKING**: `.stem` health findings no longer appear in `results[]` (they carried `source: "stem-health"` and a `.stem` path) and no longer count toward `summary.total`, `summary.valid` or `summary.warnings_count`. They move to `stem_health[]` with their own summary counts. `summary.total` is now a record count and agrees with `query --count`, `tree --field root.total` and `stats --field total` on the same path — previously it varied with schema hygiene, and `.stem` entries survived a `--where` filter they could not match.
- **BREAKING**: directory structural verdicts (trailing-slash paths such as `sub/`) moved out of `results[]` into `structural[]` and no longer count toward `summary.total`, for the same reason `.stem` findings did. An error there still exits 1.
- **BREAKING**: `validate --staged` with an empty index now emits the envelope with `summary.total: 0` instead of writing zero bytes, so `rootline validate --staged | jq -e '.summary.invalid == 0'` no longer fails in a pre-commit hook.
- `validate --all` on a tree with no `.stem`, or one that does not parse, now emits the envelope — carrying `stem-files-exist` or `yaml-valid` in `stem_health` and `scan_failed` in `notices`, still exit 1 — instead of a raw Go error on stderr and no JSON. Both checks were computed and then discarded, making them unreachable through the command.
- `validate --all` on an emptied or renamed path now reports `total: 0` plus a `no_records` notice. It previously reported `total: 1, valid: 1` — the `stem-files-exist` pseudo-record — which a CI gate read as green.
- `nested-root-marker` is now delivered at `info` severity as authored, and no longer fails `--strict`. The severity mapper handled only `pass` and `fail`, silently promoting `info` to a warning that CI could not suppress.
- `monotonic-violations` messages now name the category that was violated. Type widening, required loosening, severity loosening and structural loosening all rendered as `(type change: ...)`; structural bounds were truncated to the field `structural`, making `min_children` and `max_children` indistinguishable. They now report their full constraint path.
- **BREAKING**: `--output` is now validated against a per-command format contract instead of being a hint. An unadvertised value (`-o sdlkfj`, `-o JSON`, `-o ""`) and a format the command does not implement are both rejected before the command body runs, where they previously fell through to whatever the command's default branch emitted. `jsonl` and `csv` remain `query --select` only; on `tree` and `graph` the diagram stays bound to `-o table`; `graph --check` rejects an explicitly set `--output` rather than ignoring it. See `docs/output.md`.
- CI now runs for feature-based and stacked pull requests, while preserving the existing push and release safeguards
- License changed from PolyForm Noncommercial 1.0.0 to Apache License 2.0 — commercial use is now permitted
- picokit dependency bumped to its Apache-2.0-relicensed release, so distributed binaries no longer embed noncommercially licensed code
- **BREAKING**: Schema discovery no longer uses `.git` directory as a boundary. Projects must now declare a root marker by adding `root: true` to the project's top-level `.stem` file. Existing projects without a root marker will receive a clear error message with the fix.
- **BREAKING**: Commands that govern a project (`validate`, `fix`, `query`, `tree`, `graph`, `describe`, `explain`, `set`, `stats`) now fail instead of silently succeeding when schema discovery cannot find a `.stem` boundary. This prevents false-green validation runs over zero records.
- **BREAKING**: Projects with `.stem` files but no root marker must add `root: true` to their top-level `.stem` — one line — to use governed commands. On a terminal, rootline offers to add it interactively. Do not use `rootline init --force` to migrate: it re-infers and overwrites an existing schema. See `docs/UPGRADE.md`.
- Schema discovery is now stable: resolution depends only on the target path and filesystem `.stem` files, never on the process working directory.
- `set` command no longer requires a `.git` directory to function.
- `rootline init` now emits `root: true` in generated `.stem` files, marking new projects as their own boundaries.
- **BREAKING**: `migrate --split` now refuses to overwrite existing child `.stem` files. It stats every child target before writing anything and fails with `<path> already exists (use --force to overwrite)`, leaving all files untouched. Invocations that previously succeeded by silently clobbering child stems must now pass `--force`. The root `.stem` at the target is the input being rewritten in place and is never guarded. `--dry-run` annotates each target that would be overwritten.

### Fixed

- Corrected the canonical Rootline skill's governance guidance: `query` without `--sort`, `tree`, `graph`, and `graph --check` support schemaless records; `query --sort` and schema-dependent commands, including `stats`, require a schema. Documented the distinction between no `.stem` and an invalid or undeclared schema boundary, added runnable schemaless examples, and pinned the guidance with documentation contract assertions. Command behavior and installed skill symlinks are unchanged. Closes #295.
- Query documentation now uses bare metadata field names consistently for CLI filtering, sorting, and projection, and separates lower-level condition-tree paths and JSON output extraction from CLI expressions. Closes #296.
- Migration documentation now specifies split overwrite refusal, explicit `--force` replacement and dry-run annotations, and matches non-breaking field severity and added-rule classifications plus current output examples. Classification behavior is unchanged. Closes #297.
- `query --count -o table` now renders one `Count` column and one decimal row instead of silently emitting JSON; `-o json` preserves the version-1 `rootline/count` envelope. Query rejects count with `jsonl`/`csv`, row formats without `--select`, and `--count` with `--select` before schema discovery or scanning, while preserving JSON-only `--field` validation precedence. Closes #294.
- `concat` now renders strings unchanged, integers as base-10 text, and booleans as `true`/`false` instead of reflection debug output. Nil remains empty text; unsupported types, including lists, maps, and floats, return an explicit expression evaluation error. Closes #293.
- Bare `rootline repair` now shows grouping-command help instead of executing apply logic and failing with `--report is required`. Help and the README identify version 1 `rootline/proposals` reports generated by `rootline fix --all <dir> --dry-run -o json`; `repair apply` behavior and flags are unchanged. Closes #292.
- Query sorting now treats explicit YAML `null` and derived nil values as absent, placing them with missing keys after all non-null values in both ascending and descending order. Null/missing peers retain input order when otherwise equal, and derived nil continues to shadow frontmatter; non-null comparisons and scalar builtin sorting are unchanged. Closes #291.
- Unknown `validate[].rule` names now reject the `.stem` at parse time as `schema-valid`, naming the field, unknown rule, and supported names instead of silently skipping the constraint. `validate --all` reports the failure in `stem_health[]` and exits non-zero before document validation; `non_empty`, `exists`, `requires`, and `enum` remain supported. Closes #290.
- Query sorting now resolves the scalar builtins `path`, `body`, and `type` directly from records before same-named metadata, making `--sort path:asc` and `--sort path:desc` order paths correctly. The complex builtin `sections` is rejected explicitly even with no known fields; derived-before-frontmatter precedence for other fields, schema enum ordering, and missing-values-last behavior are unchanged. Closes #289.
- Structural `require_index` now accepts only regular files (including symlink targets), reports directories and other non-regular entries explicitly, and surfaces non-not-found stat failures as structural I/O diagnostics. Missing-file diagnostics remain unchanged. Closes #288.
- Public `StemChain`, `EffectiveSchema`, `Resolve`, and `ResolveLayered` now resolve relative record paths against the supplied root before schema discovery and match filtering, independent of the working directory when the root is absolute. Absolute paths retain their meaning, and `Resolution.Path`, chain, provenance, layer, and conflict paths remain absolute. Empty roots keep the working-directory fallback; relative roots are interpreted from that directory. Closes #287.
- `graph --check` now evaluates per-record `links.checks.cycles` opt-in against complete directed-cycle membership, so overlapping cycles fail when an opted-in member is omitted from the deterministic report. Acyclic opt-ins remain informational; explicit `--fail-cycles` overrides, reported paths, ordering, and back-edge counts are unchanged. Closes #286.
- `WalkUp` schema discovery, including request-scoped cached discovery, now skips only genuine path absence. Target-path I/O failures and unreadable or broken child `.stem` entries return contextual, wrapped errors instead of silently falling back to an ancestor; dangling symlinks are distinguished from missing entries, failures are never cached as absence, and the exact no-schema sentinel and guidance remain unchanged. Closes #285.
- Link extraction now closes fenced code blocks only on the opening marker with a run at least as long as the opener. Different markers and shorter runs remain code content, preventing wiki-links and Markdown links from leaking into graph, validation, or query results; indented fences and original link line numbers are preserved. Closes #283.
- Mermaid diagrams now use deterministic, collision-free node IDs (`n_` plus lowercase hexadecimal path bytes), so distinct paths such as `a-b.md`/`a_b.md` and `foo/bar.md`/`foo_bar.md` no longer merge nodes or attach edges incorrectly. Original path labels and sorted output are preserved, including explicit labels for unique edge targets outside the record node set; DOT and JSON are unchanged. Closes #282.
- Unchecked graph construction now resolves extension-bearing wikilinks such as `peer.md` to a same-directory record before basename fallback, so duplicate basenames no longer erase direct edges or suppress `analyze` missing-back-reference findings. Missing relative targets retain the original unique/ambiguous fallback behavior; prepared graph/query edges and Markdown paths remain unchanged. Closes #281.
- `explain` now propagates sibling filesystem scan failures for index-file aggregation as contextual errors, exiting non-zero without partial stdout or a successful null aggregate trace. Readable inputs still aggregate normally, and malformed sibling frontmatter retains its existing record-extraction semantics. Closes #280.
- `analyze` now validates link types against each record's effective inherited or overridden `links.allowed`, rather than the scan root's list. Child-only allowances no longer produce false violations, and child-only restrictions are reported. Findings remain diagnostic and schema-apply routing is unchanged; records without an allowed list retain global consensus inference. Closes #279.
- `init --template` now parses every remote `.stem` with the production schema parser before copying any files, rejecting parser-invalid YAML in installation and dry-run modes with template-relative source paths. Invalid templates leave the destination untouched, including with `--force`; parser-accepted v2 templates still copy unchanged without extra lint checks. Closes #278.
- `hooks install`, `hooks status`, and `hooks uninstall` now use Git's effective absolute hooks directory, honoring repository-local absolute and relative `core.hooksPath` settings and working from repository subdirectories. A managed hook in an unused `.git/hooks` directory no longer reports as installed. Closes #277.
- `migrate --split` now preserves every supported root structural and link-governance field through production `.stem` parsing, including `max_children`, severity-only structural declarations, link styles/checks with explicit false, basename fallback, and typed-rule `value_field`. Link governance survives empty or omitted `allowed`; children still receive only level-specific schema, with version, root-marker, and overwrite behavior unchanged. Closes #272.
- Stored `correct_link` proposals now share a first-occurrence/content-change guard across `repair apply` and legacy `fix --all` application. Stale reports, empty sources, and identical replacements are skipped without writing, changing modification times, or claiming successful changes; dry-run and reapplication agree. Legacy link repairs now enforce lexical and physical containment before document access; `repair apply` retains post-validation and rollback for real changes. Closes #274.
- `migrate` diff now populates `affected_files` through the existing classifier using records in each target `.stem`'s governed subtree, respecting effective scopes and `.stemignore` without counting siblings or independently rooted descendants. Unaffected changes retain zero, classified changes are ordered breaking-first, and version-1 JSON envelopes and table text remain unchanged. Baselines are resolved before scanning, so failures still emit no partial results. Closes #273.
- `migrate` diff now fails before rendering when an explicit `--from` baseline cannot be read or parsed, or an existing Git HEAD baseline is rejected by the parser. Only genuinely absent implicit Git baselines retain empty-schema comparison; other Git failures also fail closed. Error runs emit no fabricated additions or partial stdout and leave files untouched, including in dry-run and directory mode. Closes #270.
- `migrate` diff now reports sequence `prefix`/`digits` and field `match`/`required_match`/`excludes` edits with named before/after snapshots in the existing version-1 change list. Conditional rule identity includes `if` and `then`, so if-only and then-only edits emit removed/added rules with full snapshots instead of disappearing; JSON and table output retain deterministic ordering. Closes #268.
- `schema propose` bootstrap patches now declare `root: true` only when the scan root has no ancestor governance boundary. Standalone flat and hierarchical proposals establish a usable governed root after apply, while already-governed subtrees retain inheritance without a nested marker; `init` is unchanged. Closes #267.
- `validate --all` now applies existing structural rules to governed root and intermediate directories with descendant records even when they contain no direct Markdown records. Directory selection retains record filters and scan/governance boundaries, with lexically ordered trailing-slash paths in the unchanged v2 envelope. Closes #266.
- `schema apply` now skips empty-value `untyped_field` and `sequence_incomplete` diagnostics explicitly and rejects malformed sequence completion values, including empty prefixes. These entries no longer write empty types, mutate sequence formats, or abort valid same-field and unrelated siblings; dry-run and write modes share sorted decision ledgers without inventing missing values. Closes #264.
- `migrate --rename` now changes only a column-0 key in the leading document frontmatter, leaving nested keys untouched and preserving every other byte, including comments, indentation, body content, CRLF line endings, and UTF-8 BOMs. Real and dry-run results no longer claim updates when no key matches. Closes #265.
- `migrate --rename` now preflights destination-key collisions across every affected document and declaring `.stem` before any write. Real and dry-run modes refuse identically, preserving all document/schema bytes and leaving the migration log untouched. Closes #269.
- Boundary preflight now checks the effective `query`/`stats` target (positional path before `--from`) and the resolved `repair apply` root (`--root`, report `root`, report `path`, then report directory). Repair application consumes the same invocation-scoped report snapshot and absolute root authorized by preflight, so a changed report cannot redirect writes. Closes #263.
- `repair apply` now post-validates and atomically rolls back invalid `set_section` edits, retracting only the reverted target's changes while preserving unrelated repairs. Section, frontmatter, and link proposals share aligned change ledgers in real and dry-run modes, and successive same-file repairs retain earlier mutations. Closes #276.
- `set` now restores original document bytes atomically after post-mutation extraction, schema resolution, or validation failure, preserving file mode. A failed restore reports the original cause, absolute unreverted path, and restore error without falsely claiming rollback. Closes #271.
- Report-selected repair and schema targets now resolve existing symlinks before containment checks. Directory and file aliases that escape the scan root are rejected before access, while aliases and missing targets that remain physically inside the root retain their existing behavior.
- `graph` now orders `broken_links` by `(source, target, line, type)` and ranks equal-distance suggestions lexically before keeping the closest three, so JSON and `--check` no longer change byte output or tied suggestion membership across identical runs.
- `rootline skill install` now verifies staged symlink preimages by the link identity recorded in the plan and backup, so an Agents/Pi link pointing at the Claude destination is not falsely rejected after the same installation replaces Claude first.
- `fix` now detects native YAML timestamp, boolean and integer values in governed string fields, preserves their exact scalar text while quoting them, and reports unsupported `rule: type` mismatches under `type_findings`. Stored repair reports carry optional `from_representation` evidence and reject stale lexeme or representation changes without weakening historical `correct_value` guards. Fix findings remain informational; `validate` remains the corpus-validity command. Closes #196.
- CI ran on crossbeam's default `light` profile, so `Lint`, `Tidy` and `Vulnerability check` reported "skipping" on every run and the test job never used `-race`. `ci.yml` now passes `profile: full`, which is what `CLAUDE.md` already described.
- The lint job could not have passed even once it was enabled: crossbeam pins `lint-version` `v2.10.1`, built with go1.26, while the job resolves Go from `stable` — now 1.27 — so the linter panicked with `file requires newer Go version go1.27`. `ci.yml` now pins `v2.13.1`. Raise it again whenever the runner's stable Go moves ahead of crossbeam's default.
- `validate <file>` and the boundary preflight now emit the `rootline/validate-batch` v2 envelope carrying a `schema_resolution_failed` error notice, instead of writing a raw Go error to stderr and nothing to stdout. The guarantee already held for `validate --all`; a file target and the preflight were the two paths that broke it. Both still exit 1. A file target and `--all` also reach the same verdict on an undeclared boundary, so naming a file cannot relax governance.
- Declining the interactive root-marker migration prompt now refuses to run the command, matching the non-interactive behavior. Both paths report `schema_resolution_failed` in the envelope and exit 1.
- `stats` now applies `scope.match` filtering like `query`, `tree`, `graph`, and `validate --all`, so the four commands report consistent counts over the same directory.
- `query --where 'type == ...'` now works correctly. The expr-lang `type()` builtin function is disabled at compile time, so `type` always refers to the record field, never the function. Calling `type(x)` as a function in `--where` is no longer supported; use the field name instead.
- **BREAKING**: a child `.stem` no longer removes an inherited key in any section. `null` in `derive:` or `aggregate:` keeps the parent's value instead of deleting it, and a `null` field in `schema:` is refused when the file is read. Removal let a child drop a parent's declaration, which reduced the guarantee that parent made to everything beneath it. A field that should not exist is removed from the `.stem` that declares it.
- A `null` `schema:` field used to surface as three unrelated diagnostics — `incomplete-type`, a `required` loosening, and a type change to `""` — none naming the real mistake. The read now refuses it with one message that does.
- `schema apply` now emits the result envelope (`rootline/schema-apply` version 1) to stdout before exiting non-zero on errors, so the structured result is always available even when the run fails. Previously, errors in the analyze-report path wrote raw Go errors to stderr with no JSON output.
- YAML timestamp values (unquoted dates like `2026-06-24`) now report as `"timestamp"` in validation error messages instead of `"mapping"`, making the type mismatch clear. Other struct types continue to report as `"mapping"`.
- `analyze -o json` now emits each category's inference array in a stable lexical total order instead of exposing randomized Go map traversal. Identical inputs are byte-identical while the version 1 schema, category order, inference membership, and summary counts remain unchanged.
- `migrate --split` emitted child `.stem` files without a version key, so every child parsed as version 0 and the loader rejected it with `stem version 0 is no longer supported`. Child stems now carry `version: 2`.
- `migrate --split` dropped `root: true` from the regenerated root `.stem`, leaving the project with no declared boundary: walk-up escaped into ancestor `.stem` files and `validate --all` failed with `Schema discovery reached the filesystem root without finding a declared boundary`. The marker is now preserved when present (and not invented when absent).
- Graph and tree output is now deterministic. `graph` derived its node and edge arrays from map iteration, which Go randomizes per run, so JSON, DOT and Mermaid emitted a different order on every invocation. Nodes are now sorted lexically by path, edges by `(source, target, line, type)`. `tree` picked its status column by taking whichever enum-typed schema field the map happened to yield first; it now sorts the enum field names and takes the first, at both decision sites. JSON stays at `"version": 1` — same keys, same types, same elements, only the order is now fixed. Multi-enum corpora see a stabilized status column: this repository's `docs/roadmap` reliably shows `estado` instead of alternating with `tipo`.
- `graph` cycle enumeration is now deterministic. The determinism fix above sorted nodes and edges but left cycle detection rooting its DFS in map iteration order, so identical input still produced a different cycle rotation and a different outer ordering on every run — in both the JSON `cycles` array and the numbered `--check` enumeration — and on graphs with overlapping cycles a different cycle *count*. DFS roots now come from the same sorted node order the renderers use, adjacency is de-duplicated and sorted so the result no longer depends on scan order, each cycle is rotated to start at its lexicographically smallest member, and the list is de-duplicated and sorted. JSON stays at `"version": 1` — same keys, same types, only the order is now fixed. A document linking twice to the same target used to emit the same cycle twice; it is now reported once. Detection semantics are unchanged: this is back-edge detection over a canonical spanning forest, so `len(cycles)` counts detected back edges, not distinct elementary circuits.
- False-green validation: `validate --all` on a directory outside any schema now correctly exits with an error instead of succeeding with zero validated records.
- Schema discovery boundary violations: walking up the filesystem no longer accidentally collects `.stem` files from outside the project (e.g., from home directory).
- Working directory dependence: schema resolution is now stable regardless of where commands are invoked from.

## [v9.12.2] - 2026-08-21

### Changed

- **Compatibility correction** (formerly documented as `Compatibility correction (unreleased)`): active schemas and guidance use canonical strict types (`string`, `list`, `enum`, `sequence`, `link`, `boolean`, `integer`) with no coercion. Historical `type: section` plus `heading:`/`ordered:` declarations migrate to `type: string` plus `source: body.section["## Heading"]`; `type: bool` migrates to `type: boolean`; historical `enum:` keys migrate to `values:`. Empty-present sections satisfy presence, duplicate matching headings fail, inherited source bindings remain stable, and public validation error sources are governance-root-relative. See `docs/UPGRADE.md` for paired before/after examples; ancestor-qualified selectors remain deferred to #190.
